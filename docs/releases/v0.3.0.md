# SceneIO 0.3.0

SceneIO 0.3.0 turns the initial compiled I/O tier into a broad, bounded 3D-CV
interchange layer while preserving the package's NumPy-only base dependency
and explicit contract-first behavior.

## Highlights

- The built-in registry grows from 23 to 74 formats. All 74 formats support
  reads and inspection, 73 support writes, 37 expose 43 bounded partial
  selectors, all 74 stream reads, and 71 stream writes.
- New format families cover reconstruction and calibration artifacts, dense
  geometry, point clouds and scans, Gaussian splats, polygonal meshes and
  mixed scenes, scientific containers, visual-inertial datasets, dense label
  maps, and image/video sequences.
- Every built-in format now exposes an immutable coordinate convention
  contract. Conversion is explicit, targets the documented COLMAP convention,
  and refuses unknown or unsupported transforms instead of relabeling data.
- All 100 public in-memory data representations now have versioned structural,
  scale, unit, coordinate-source, conversion, and refusal policies.
- Visual-inertial records and bounded EuRoC dataset I/O, typed semantic,
  instance, and panoptic labels, typed multi-scan E57 data, `SceneGraph`, and
  explicit Gaussian semantics close the finite 3D-CV follow-on profile.

## I/O and packaging hardening

- Transactional writers avoid publishing partial outputs, while direct-sink,
  memory-mapped, streaming, and partial-read paths are exposed only where
  their format contracts can preserve the requested semantics.
- Optional, permissively licensed providers remain lazy and independent.
  Extras are available for HDF5, Zarr, NCore V4, TIFF, E57, Arrow/Parquet,
  OpenVDB, AVIF, and USD/USDZ; NumPy remains the only base runtime dependency.
- Native sources used by the wheel builds are repository-contained. The
  release gate verifies repository-to-sdist source closure before building
  platform wheels.
- Frozen backend-qualification configuration identities are canonicalized
  across LF and CRLF checkouts, so the same evidence contract is portable
  across development platforms.
- The release matrix builds and smoke-tests a CPython 3.12 stable-ABI wheel on
  manylinux2014 x86-64, Windows AMD64, and macOS arm64, plus an sdist. Dedicated
  sanitizer, OpenUSD, Niantic SPZ, and optional-provider checks cover the
  bounded interoperability profiles.

## Compatibility and boundaries

- Python support remains `>=3.12,<3.13` for this release.
- Existing format IDs and the public `sceneio` contract namespaces remain in
  place. Readers and writers are stricter where accepting an input would lose
  coordinate, scale, animation, material, label, or container semantics.
- SceneIO intentionally implements documented 3D-CV subsets rather than acting
  as a general scene-authoring, media-editing, or scientific-computing stack.
  Unsupported profiles fail explicitly.
- The optional TinyUSDZ provider has a newer Linux runtime floor than the base
  manylinux2014 SceneIO wheel; see the
  [format coverage contract](../format_coverage.md) for provider-specific
  limits.
